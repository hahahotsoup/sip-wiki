# 关于 sip

> **——「品，你细品。」**
>
> **sip：你的信息，你的历史，你的判断。**

sip 是一个**本地优先的个人信息库**：从 RSS 等来源收集内容，在本地长期保存并追踪变化，通过搜索、筛选和 Agent，让你更好地掌控自己的信息输入。它帮你完成五件事——**收集、保存、追踪、筛选、使用**。

它不是算法推荐阅读器，也不是让你"刷更多"的资讯流。**AI 帮你理解信息，但不替你决定信息的价值**——判断权永远在你。

## 设计理念

| 原则 | 说明 |
|------|------|
| **本地优先** | 数据在你自己手里（SQLite + 文件缓存），不需要账号，不上传阅读记录 |
| **透明决策** | 只看你订阅的源，没有算法黑箱；过滤规则就是你维护的订阅源列表 |
| **版本即事实** | 作者改了什么？什么时候改的？sip 帮你全程记录，不丢失任何历史 |
| **AI 只读白名单** | AI 摘要和语义搜索，只基于你信任的订阅源，杜绝低质引用 |
| **判断权在你** | AI 帮你理解信息，但不替你决定信息的价值——所有决定（筛选、降频、归档）都经你确认 |
| **开箱即用，极轻量** | 单文件 exe，零依赖，启动即用；AI 能力按需调用，不预跑 |

**设计边界**：sip 只做两件事——**确定性的规则** 与 **本地事实的存储**。你在意的收集、保存、追踪、筛选、使用，全都建立在这两件事之上；凡是需要判断/解释/对话的，都交给 agent 与用户。今日哈汤的选文规则保持固定、可解释；个性化等"智能"等 telemetry 数据足够后，要么以新的确定性规则实现，要么放在 agent 层——不进程序。

它不会让你刷更多，但它会让你读得更安心。
