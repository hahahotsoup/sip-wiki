# 实战场景：6 个把 sip 用起来的落地工作流

> 这一页不做功能介绍，只给你**照着抄就能跑**的真实工作流。每个场景都有：目的、步骤、以及"看到什么就算成了"。

---

## 场景 1：让 AI 只从你信任的源回答问题

**目的**：你或你的 Agent 查资料时，不再引用搜狐、百家号。

**步骤**：

```bash
# 1. 添加你信任的源（可批量导入 OPML）
sip -d https://blog.hotsouprealm.top/atom.xml
sip --import-opml 你的导出.xml

# 2. 配置 AI（首次一次性）——选 Embedding/LLM 提供方，输入 API Key
sip --init

# 3. 向量化（把文章转成语义向量）
sip --index

# 4. 开查！AI 只会返回你订阅的源里的文章
sip --search "你要查的话题" --json
```

**看到什么就算成**：`--search` 返回的每条结果，来源都落在你的订阅源列表里（`sip -l` 核对）。

**进阶**：

- 想让别人（父母/朋友）的 AI 也用？把 [sip-rss skill](/使用/Bot) 和这份**系统提示词**喂给 Agent：

```
查资料先跑 sip --search "关键词" --json，只引用返回的可信源；
汇总时注明每条信息来源与链接；不确定就明说"未查到"，不要编造。
```

## 场景 2：追踪一篇文章被改了什么

**目的**：某篇重要文章（政策、公告、教程）被作者悄悄改稿时，你要第一时间知道。

**步骤**：

```bash
# 1. 每天更新一次订阅源
sip --sync                  # 只更新「到期」的源；或 sip --update-all 强制全更

# 2. 看今天谁改过文章
sip --today                 # 顶部「今日变化摘要」列出被改的文章与改动概览

# 3. 深入看某篇的修改历史
sip --versions 42           # 有哪些版本、什么时候改的
sip --diff 42               # 最近两版改了哪些内容
sip --diff 42 v1 v3 --json  # 指定两版对比，结构化输出
```

**看到什么就算成**：`--diff` 输出增删行与前后文变化，而不是"有更新"三个字。

> 作者改稿后 TUI 里标题带 **`✎`** 标记，选中按 `V` 直接看版本。这就是"版本即事实"。

## 场景 3：每天 5 分钟，读「该读」的

**目的**：不被无限信息流淹没，每天固定一碗，读完就关。

**步骤**：

```bash
# 1. 给源设置更新计划（不浪费资源，到期才拉取）
sip --schedule 1 daily@08:00     # 源 1 每天早 8 点更新
sip --schedule 2 30m             # 源 2 每 30 分钟更新（比如新闻源）

# 2. 打开 TUI 时，它会自动静默同步到期源
./sip.exe

# 3. 或直接在命令行看今天的清单
sip --today                      # 今日 5 篇选文 + 预估时长 + 理由
sip --today --refresh            # 想重选一碗
```

**看到什么就算成**：`--today` 给出 5 篇以内的清单，每篇附"为什么选它"。全读完或标记跳过，一天的信息摄入就闭环了。

## 场景 4：给不会分辨真假的家人配一台"安心阅读器"

**目的**：父母/长辈打开就能看，垃圾源早已被挡在外面。

**步骤**：

```bash
# 1. 只订阅你审核过的源（央视、本地气象、你信任的医学号）
sip --onboarding               # 看内置推荐模板（按领域一键加源）
sip -d https://你审核过的源/rss

# 2. 摘要过短的文章会自动提示抓全文，慢慢读
sip --fulltext 12              # 抓原文到本地缓存

# 3. 他们只需要记住一件事：打开 sip → 上下选择 → 回车读
./sip.exe                      # TUI 界面，全键盘，无广告无推荐流
```

**看到什么就算成**：家人能自己打开 TUI、读一篇、退出，中间不用你帮忙。

> **隐私边界**：阅读记录全在本机 `readwithhotsoup/`，不上传、无账号。遥测（苏暖泉）默认关闭，家人在界面上不会被打扰。

## 场景 5：把 sip 挂到 QQ / 微信 / Discord / Telegram 群里

**目的**：你在群里 @ 机器人，它用 sip 检索，只从你订阅的源回答。

**步骤**：

```bash
# 1. 按 Bot 接入教程装好 OpenClaw（或 Cherry Studio）
# 2. 把 sip.exe 放进 PATH，把 sip-rss skill 放进 Agent 技能目录
# 3. 粘贴系统提示词（含 "查资料先跑 sip --search" 规则）
# 4. 在群里 @ 它
```

```text
@bot 最近两天有哪些值得读的 RSS 更新？   → 执行 sip --today --json
@bot 帮我查一下 "LLM Agent" 相关文章     → 执行 sip --search "LLM Agent" --json
```

**看到什么就算成**：bot 返回可信摘要并附来源链接，且引用源都在你的白名单内。

**完整教程**：[Bot 接入](/使用/Bot)。

## 场景 6：信息摄入闭环——越用越干净

**目的**：让订阅源本身持续优化，信息流越用越「对」。

**步骤**：

```bash
# 1. 看阅读事实（不替你下结论）
sip --insights                 # 每个源：打开/读完/完成率/跳过/点赞

# 2. 对不满意的地方做「决策」——规则经你确认才生效
sip --policy lower_frequency --feed 3   # 源 3 更新太频繁 → 降频
sip --policy archive --feed 5           # 源 5 不想看 → 归档
sip --policy tag #干货 --feed 2        # 源 2 打标签

# 3. 跨源重复的文章，看 diff 确认后隐藏（数据保留，可撤销）
sip --dedup scan                # 标出「可能同文」——输出重复簇（代表 + 成员）
sip --dedup hide-cluster <代表Id>  # 一键隐藏整簇（保留代表，隐藏其余成员）
sip --dedup undo <key>          # 反悔了撤销（key 见 list 输出）
```

**看到什么就算成**：`--insights` 有事实数据、`--policy` 生效后 `-l` 显示对应标签/频率变化。**AI 永不自动写规则**——每个决定都 `createdBy: user`。

## 常见问题

| 问题 | 答案 |
|------|------|
| `--search` 报「AI 未配置」 | 先 `sip --init` 配模型；提示没索引就跑 `sip --index` |
| 摘要太短读不过瘾 | `sip --fulltext <id>` 抓全文，`--show` 时自动优先用全文 |
| 想每天固定时间更新 | `sip --schedule <id> daily@HH:mm`，到期才拉取 |
| 新文章当天没进今日清单 | 今日清单当天有缓存（一天固定一碗）；读新内容直接 `sip --grep` / `--show` |
| 想从 FreshRSS 搬过来 | 导出 OPML → `sip --import-opml 文件.xml` |
