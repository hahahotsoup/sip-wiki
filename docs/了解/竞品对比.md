# 竞品对比：sip 和他们有什么不同

> **——「品，你细品。」**

订阅阅读器的生态很拥挤。sip 不打算在"聚合订阅、展示文章"上跟它们拼——那些功能它们都做得很好。sip 想做的，是它们**普遍没做、也不打算做**的事：让信息可信、可追溯、可被 AI 使用。

下面按三类常见选择展开对比。先看共性结论，再看分项。

## 一句话定位

| 类型 | 代表 | 核心体验 | sip 与它们的差异 |
|------|------|----------|------------------|
| 自托管网页阅读器 | FreshRSS、Tiny Tiny RSS、Miniflux | 自己部署，浏览器聚合阅读 | sip 是本地单文件，且多了版本追踪 / AI 白名单 / 每日一碗 |
| 云端聚合服务 | Feedly、Inoreader、The Old Reader、NewsBlur | 托管聚合，多端同步 | sip 数据在自己手里，无账号、不上传；AI 检索只读白名单 |
| 桌面 / 移动客户端 | Reeder、NetNewsWire、Follow | 好看好用的本地阅读界面 | sip 是 CLI + TUI，为脚本 / Agent 而生，不只是给人看的 UI |

## 自托管派：FreshRSS / Tiny Tiny RSS / Miniflux

它们都帮你"聚合订阅、在浏览器里读"。这部分的成熟度很高，sip 不重复造轮子。

**sip 多出来的**（这页不展开细节，命令都真实可跑）：

| sip 能力 | 它们能吗 | 具体体现 |
|----------|----------|----------|
| 版本追踪 + Diff | ❌ 只显示"有新文章" | `sip --versions 42` / `sip --diff 42`——作者改稿、更正、删争议，全被记录下来 |
| AI 只读白名单 | ❌ | `sip --search "话题" --json`——AI 语义检索 / 摘要只来自你订阅的源 |
| 每日一碗 | ❌ 给你无限信息流 | `sip --today`——每天固定 5 篇规则式选文，防刷防茧房 |
| 面向 Agent 的 CLI | ⚠️ 有 API 但偏重、面向人 | 统一 JSON + 结构化退出码 + [sip-rss skill](/使用/Bot)，可直接挂进 bot |
| 部署形态 | 服务器 + 数据库 + Web | 本地单文件 exe，`readwithhotsoup/` 里全是你的数据 |

## 云端派：Feedly / Inoreader / The Old Reader / NewsBlur

它们的强项是"托管 + 多端同步 + 推荐算法"。

**sip 的差异**：

- **数据归属**：它们把阅读记录、源列表存在云端；sip 全部在本地 `readwithhotsoup/`（SQLite + 文件缓存），不需要账号，不上传阅读记录。
- **透明决策**：云端的"推荐给你看这个"是黑盒；sip 的过滤规则就是你维护的订阅源列表，每个推荐都能说出"为什么"（[透明决策](/了解/介绍)）。
- **AI 能力**：云端大多没有"让 AI 只读你的白名单"的能力——它们要么没有 AI，要么 AI 依然会引用全网垃圾源。

## 客户端派：Reeder / NetNewsWire / Follow

它们把"读"这件事的界面做到极致。sip 的 TUI 和沉浸阅读向它们致敬，但定位不同：

- **它们是给人看的 UI**；sip 是**给人 + 给 AI 用的工具**——同一份数据，人用 TUI 读，Agent 用 `--search --json` 查。
- 客户端一般不解决"文章被改"和"AI 引用可信源"这两个问题；这正是 sip 的核心。

## 共同盲区：三件事几乎没人做

不管哪一类，绝大多数阅读器都卡在同一个地方——**只做"聚合 + 展示"，不做"信任 + 使用"**：

| 盲区 | 传统阅读器 | sip |
|------|------------|-----|
| 作者改稿，改了什么 | 你永远看到旧版 | `--diff` 展示变化轨迹（[智能归档](/参考/功能)） |
| 想用 AI 查资料，又怕它引用垃圾源 | 无解 | AI 只检索你订阅的源（[AI 友好](/参考/功能)） |
| 信息过载，刷不停 | 给你更多 | 每日一碗，读完就关（[今日哈汤](/参考/功能)） |

## 什么时候不该用 sip？

诚实一点，这些场景 sip 不适合：

- 你要一个**网页端**、手机浏览器随时访问的阅读器 → 选 FreshRSS / Miniflux 这类自托管。
- 你要**多人在线**共用一套订阅与账户 → 选自托管或云端。
- 你只是想把 200 个源聚在一处，对"文章被改""AI 引用"不关心 → 任何主流阅读器都够。
- 你已经有成熟的部署，迁移成本高 → 不必强换。

## 迁移过来？

主流阅读器都支持 OPML，sip 也一样：

```bash
sip --import-opml 你的导出.xml     # FreshRSS / Feedly / Inoreader / TT-RSS 都能导出 OPML
sip -l                             # 确认订阅源都进来了
```

> 想并行试一周也不冲突：旧阅读器归快速浏览，sip 归精读与 AI。留理由充分的那个，删多余的那个。
